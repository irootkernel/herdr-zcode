Mulgae requested these additions in its `EPIC-019` Sorage Handoff, revision `1`, against herdr-zcode `0.1.0` at `c986977`. ZCode.app `4.0.0` bundles catalog revision `44`, which lacks GLM-5.4. The current projected `--auth-file` path selects the bundled catalog because it skips native Desktop cache and environment-override discovery. Mulgae owns sandbox admission, review prompts and staging, package policy, and downstream qualification.

## TASK-007: Bind an explicit catalog in projected mode

Add `--catalog-file <path>` for `--auth-file` sessions in both `--runtime tui` and `--runtime core`. Require `--auth-file` at argument parsing. Resolve relative paths against `--cwd`, as for the auth file. An explicit catalog takes precedence in projected mode and is compatible with `--no-copy-catalog` and `--skip-desktop-inspect`. Preserve bundled selection for projected sessions without the flag and keep the Desktop login path's current selection behavior.

- Open the file read-only with `O_NOFOLLOW | O_NONBLOCK` and compare initial `lstat` and opened-descriptor identity. Require a regular single-link file owned by the invoking UID, with group and other write bits clear and a size from 1 byte through 4 MiB. Bound the descriptor read and recheck identity, metadata, and length before accepting its bytes. `0644` is valid under this permission rule. Reject `0664` and `0666`.
- Parse strict UTF-8 JSON. Require a top-level object, `schemaVersion: 1`, a positive safe-integer `revision`, and a plain-object `config.modelConfigRules`. In `config.providerConfigRules.providerRules`, require one Coding Plan rule for the projected `providerId` with the expected `config.access` and a valid `config.builtinModelIds` list. Require the rule's `config.api.type` and full HTTPS `config.api.baseUrl` strings to match the corresponding trusted bundled rule exactly. Both fields match in the observed rev `44` bundle and rev `48` cache for ZCode.app `4.0.0`. Reject an explicit invalid catalog, including a mismatch in either API field, with a safe `catalog_invalid` diagnostic and no bundled fallback. Report a legitimate API change as a compatibility issue for this adapter. Noninteractive Core reports catalog failure as `error` and reserves `blocked:kind=auth` for credential failures.
- Copy the validated bytes to the private runtime directory by default. For `--no-copy-catalog`, use the original path and recheck it against the validated file's identity and metadata before spawn. The caller keeps the file and its path stable for the app-server's lifetime. Pass the parsed, validated catalog into `projectedAccount` instead of reopening the file there. Use the same effective absolute path for the account overlay revision and `ZCODE_BUILTIN_PROVIDER_CONFIG_FILE`. Projected mode uses disposable app state and skips native Desktop account, Keychain, and `codesign` access. If startup fails before auth consumption, the caller owns wiping and removing the leftover auth file.
- With model and effort omitted, preserve the server-reported defaults for the fresh projected session. Native Desktop last-used settings are outside that session's state. With only a model specified, use that model's advertised default effort. With only effort specified, retain the server-selected model. In noninteractive Core, stop before sending a prompt to the app-server if an explicit effort conflicts with the RPC or subscription response, or if neither provides evidence it was applied. Preserve the existing model-plus-effort checks and distinguish safe model-selection diagnostics from authentication failures.

Use synthetic rev `44` and rev `48` fixtures and the existing fake app-server tests. Verify GLM-5.4 with `max`, the three omission combinations, unsupported models and efforts, and unreported explicit effort in noninteractive Core. Exercise copy and in-place binding and ensure the catalog used by the child matches the account overlay. Cover symlinks, hardlinks, special files, owner mismatch, writable modes, oversize data, failed metadata rechecks, malformed UTF-8 and JSON, missing or ambiguous rules, and mismatched API settings. Verify that credential consumption still happens before app-server spawn and that projected sessions leave native Desktop state untouched.

## TASK-008: Report offline Desktop compatibility

Add `herdr-zcode --check-desktop --json [--app-bundle <path>]` as a standalone mode. Require `--json` and reject session flags and conflicting modes. Use the existing app bundle resolution and minimum from `toolchains.env`. Extend `inspectDesktop()` with typed inspection failures and reuse it for compatible bundle metadata. Check `Contents/Info.plist`, executable `Contents/MacOS/ZCode`, `Contents/Resources/glm/zcode.cjs`, and the bundled provider catalog at `Contents/Resources/config/provider/zcode-builtin.json`. Validate the bundled catalog with the Task 007 schema and Coding Plan rule checks. Check embedded Node and Electron without launching app-server, reading Desktop account data, opening Keychain, or making network requests.

Success is one stdout JSON object and exit `0`, with these fields:

```json
{
  "compatible": true,
  "appVersion": "4.0.0",
  "build": "example-build",
  "minZcodeAppVersion": "3.18.2",
  "appBundle": "/Applications/ZCode.app",
  "nodeVersion": "20.19.0",
  "electronVersion": "example-electron-version"
}
```

Compatibility failure is one stdout JSON object and exit `1`, with `compatible: false`, `reason`, a safe `message`, `appVersion` (the observed version or `null`), `minZcodeAppVersion`, and `appBundle` (the resolved candidate path). Report the first observable failure in this order: `app_bundle_missing` for an absent bundle, `app_bundle_invalid` for missing or malformed required metadata or files, `app_version_below_minimum` for a valid version below the floor, and `embedded_runtime_invalid` for a runtime that cannot execute or fails the embedded runtime probe, including Node below 20. If a bootstrap failure prevents full catalog validation, classify it with the checks available to the launcher. Require full validation before returning success. Use the same response shape with `invalid_arguments` for usage failures recognized in this mode.

Handle diagnostic-mode bootstrap failures both in the installed shell launcher and at the JS toolchain guard, which currently runs before argument parsing. When JS cannot start, the launcher reads the minimum from `toolchains.env`, obtains the app version from the plist when available, and serializes a properly escaped JSON object using macOS system tools. Bound the embedded runtime startup and suppress partial probe output. Reuse this structured failure path for `prepare-isolated` in Task 009. Preserve the normal launcher behavior for sessions. Keep `./dev doctor --desktop` and standalone inspection aligned on bundle checks. Test a compatible fallback and each failure reason through the installed launcher from `/private/var/empty` with an empty `HOME`, unset `NVM_DIR`, and `PATH=/usr/bin:/bin`. Include paths that require JSON escaping, unlaunchable or too-old embedded Node, and fixtures that detect app-server, account, Keychain, or network use.

## TASK-009: Prepare isolated inputs on the trusted host

Add `herdr-zcode prepare-isolated --out-dir <path> [--app-bundle <path>] [--json]`. Both forms emit a single JSON object on stdout. The command runs outside the sandbox from `/private/var/empty` with the host login's `HOME`, `PATH=/usr/bin:/bin`, `TMPDIR=/tmp`, and no `NVM_DIR`. Mulgae supplies a minimal environment. For this command derive account paths from host `HOME` and use the default cache endpoint. Ignore ambient Desktop data, endpoint, catalog, and credential-secret overrides. Use an explicit `--app-bundle` or default to `/Applications/ZCode.app`. Reuse Desktop inspection and the signed Keychain path. Extract an internal account-read operation that returns `providerId`, `identity`, and `apiKey` to the file writer without selecting a model or exposing the credential in a CLI response.

Select raw bytes from the version- and endpoint-scoped cache only if it passes the full Task 007 validation and its revision exceeds the bundled revision. An absent, unreadable, invalid, or older cache uses the validated bundled catalog, as requested by Mulgae. Report that choice in `catalogSource` and `catalogRevision`. If the bundled catalog fails validation, return `catalog_invalid`. An explicit GLM-5.4 selection against a bundled catalog without that model fails as a model-selection error.

Budget 12 seconds from command entry, including launcher and probe work, with the final 2 seconds reserved for cleanup. Carry one deadline across launcher bootstrap, bundle inspection, and signed Keychain helpers. Pass its cancellation signal through to subprocesses and stop starting work when the cleanup reserve begins. Mulgae's outer cap remains 15 seconds. Test deadline propagation with stalled probe and credential helpers.

Before accessing the account, open the existing output directory with `O_DIRECTORY | O_NOFOLLOW` and require exact `0700` and caller ownership. Compare the held descriptor with the path's `lstat` device and inode before and after each path-based operation. Check opened output descriptors for identity, owner, link count, and mode. This detects observed path changes. Callers keep the private directory and its ancestors stable because Node's path-based operations cannot exclude races with the same UID.

Reserve `catalog.json` first, then `auth.json`, using `O_CREAT | O_EXCL | O_NOFOLLOW`. Only start writing credentials after both files are reserved. Refuse any pre-existing output. With two concurrent calls to an empty directory and no other failure, only one can succeed and the loser leaves the winner's files alone. Emit the receipt after both outputs are complete.

| Output | Mode | Contents |
| --- | --- | --- |
| `auth.json` | `0600` | At most 64 KiB of UTF-8 JSON with `providerId`, `identity`, `apiKey`, and `accountAccess`. `accountAccess` is the object `{ "type": "zhipu-account", "mode": "individual-coding-plan", "accountType": "zai" }` accepted by the existing parser. |
| `catalog.json` | `0400` | At most 4 MiB of the exact selected catalog bytes, validated as in `TASK-007`. |

On ordinary failure or catchable `SIGINT`, `SIGTERM`, or `SIGHUP`, cancel pending helpers and run cleanup. Zero-fill credential bytes on the invocation's auth descriptor before unlinking the confirmed owned path, remove the invocation's catalog, and preserve pre-existing or replaced files. Mulgae owns namespace cleanup after forced termination or an unsuccessful local cleanup. The preparation command only reads native Desktop state and Keychain entries.

The success receipt fields are `authFile`, `catalogFile` (canonical absolute paths), `catalogRevision`, `catalogSHA256` (lowercase SHA-256 of the output bytes), `catalogSource` (`desktop-cache` or `bundled`), `appVersion`, `minZcodeAppVersion`, `providerId`, and `accountIdentitySHA256` (lowercase SHA-256 of the UTF-8 identity). The identity hash is a correlation value. Keep it out of general-purpose logs. Mulgae passes the returned `catalogFile` unchanged to `--catalog-file ... --no-copy-catalog`, preserving the path used by revision binding.

On failure, emit one stdout JSON object containing a safe `reason` and `message` and exit `1`. Reuse Desktop compatibility reasons. Use `invalid_arguments` for usage, `output_dir_invalid` for directory admission, `output_exists` for an exclusive-create conflict, `desktop_account_unavailable` or `desktop_keychain_unavailable` for the corresponding account failure, `catalog_invalid` for rejected catalog data, `preparation_timeout` for a deadline, `preparation_interrupted` for a catchable signal, and `projection_failed` for remaining output or cleanup failures. Route shell bootstrap, toolchain guard, and parse errors through this format. Keep raw keys, identity, credentials, headers, and internal errors out of stdout and stderr.

For `0.2.0`, retain `name`, `version`, `runtimes`, `osc7501`, and `minZcodeAppVersion` in `--version --json` and add `capabilities: ["core", "osc7501", "catalogFile", "prepareIsolated", "checkDesktop"]`. Include every new runtime module in `package.json`'s `files`. Extend the [existing live Core harness](../app-server.md#live-herdr-core-certification) in this Task with an explicit installed-candidate scenario that uses the real `prepare-isolated` command and captures the evidence described below. Keep the baseline scenario available for regression work.

Verify cache precedence and fallback, exact bytes and digest, valid mode bits, rejection of symlinked or nonprivate directories, refusal and preservation of pre-existing outputs, concurrent invocation, partial-write and signal cleanup, deadline handling, and absence of test secrets in both streams. Verify a single safe JSON result for usage, launcher, account, and output failures. Use the native host login only for the separately authorized preparation and live checks.
